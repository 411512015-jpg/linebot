一、專題改善動機與計畫調整說明

在第一版（v1.0）繳交後，經過實際雲端運作與自我檢驗，發現系統存在三項關鍵問題，因此與 AI 協商擬定改善計畫：

  • 1. 伺服器時區偏差問題 (嚴重 Bug)： 第一版使用 new Date().toLocaleString('zh-TW') 查詢時間，因 Render 雲端主機預設為 UTC 時區，導致機器人回傳的時間比台灣時間慢了 8 個小時。
  • 2. 缺乏實質核心功能與防呆： 第一版僅具備簡單覆讀機功能（你說了：XXX），當使用者傳送未完整參數（如缺少參數的指令）或非支援指令時，機器人無法給予有效反饋或引導。
  • 3. 機敏資訊管理風險： 第一版中包含真實 Access Token 的 .env 檔案曾被追蹤，需抽離並提供 .env.example 佔位檔，符合雲端安全規範。

四、核心改善程式碼實作 (Node.js)

1. 時區偏差解決方案 (Asia/Taipei 綁定)

function getTaiwanTimeString() {
  return new Intl.DateTimeFormat('zh-TW', {
    timeZone: 'Asia/Taipei',
    year: 'numeric',
    month: '2-digit',
    day: '2-digit',
    hour: '2-digit',
    minute: '2-digit',
    second: '2-digit',
    hour12: false,
  }).format(new Date());
}

2. 輸入不完整與防呆邏輯實作

// 判斷指令是否缺少必要參數
if (userText === '新增' || userText.toLowerCase() === 'add') {

} else if (userText.startsWith('新增 ') || userText.startsWith('新增')) {

五、已知限制與未來展望

  • 資料持久化（Persistence）： 當前版本使用記憶體（Map）儲存各使用者之待辦事項，若 Render 主機重新啟動或自動重佈署，資料會被清空。未來可串接雲端資料庫（如 Supabase、MongoDB Atlas）持久化保存。
  • 免費伺服器休眠機制： Render 免費層在 15 分鐘無連線時會休眠，首次喚醒需 30~50 秒。本版本已增設 /health 喚醒端點，未來可搭配定時 Ping 服務維持活躍。
  • 進階自然語言理解 (NLP)： 未來可進一步串接 Gemini / OpenAI API，讓使用者能用語音或口語（如：「幫我記一下明天下午要交作業」）自動分析成待辦項目。
